# TinyCC for ChrysalisOS Build Guide

## Overview

This guide explains how to build TinyCC (a self-hosting C compiler) as a toolchain component for ChrysalisOS. The goal is to enable **on-device C compilation** inside ChrysalisOS via the built-in `cc` command.

## Key Changes from Standard TinyCC

The standard TinyCC build produces executables with dynamic linking and a Linux ELF interpreter reference (`/lib/ld-linux.so.2`). ChrysalisOS, being a minimal 32-bit x86 operating system, does not provide this Linux-compatible loader.

Our modifications to TinyCC ensure that:

1. **TinyCC compiler (`tcc`) binary**: Remains a host compiler (can be a Linux binary).
2. **Compiled programs from tcc**: Produce **interpreter-free static binaries** by setting `CONFIG_TCC_ELFINTERP=""` (empty string).

This allows TinyCC to generate ChrysalisOS-native executables that load directly without requesting a dynamic interpreter, making them compatible with ChrysalisOS's custom ELF loader.

## Building TinyCC for ChrysalisOS

### Prerequisites

- 32-bit GCC/binutils support (install with `gcc -m32` or a 32-bit cross-compiler).
- Standard development tools (make, bash).

### Build Steps

1. **Set the cross-compiler** (if using a custom i386 ELF cross-compiler):

   ```bash
   export CHRYSALIS_TCC_CC=i386-elf-gcc
   export CHRYSALIS_TCC_AR=i386-elf-ar
   export CHRYSALIS_TCC_RANLIB=i386-elf-ranlib
   ```

   Or rely on auto-detection (the script will try `i386-elf-gcc` or fall back to `gcc -m32`).

2. **Run the build script**:

   ```bash
   cd os/ported-langs/C/toolchain
   ./build_tcc.sh
   ```

   This will:
   - Configure TinyCC with `CONFIG_TCC_ELFINTERP=""` to disable Linux interpreter embedding.
   - Build TinyCC as a static 32-bit binary.
   - Install the binary to `bin/tcc`.

3. **Verify the build**:

   ```bash
   ./bin/tcc --version
   ./bin/tcc -c <test.c>  # Test compilation
   ```

## Modifications Made

### 1. **`build_tcc.sh`**
   - Added fallback detection for i386 cross-compilers (`i386-elf-gcc` or `gcc -m32`).
   - Exports `CFLAGS` to force `CONFIG_TCC_ELFINTERP=""`.
   - Runs a post-configure `sed` to preserve the empty string in the generated `config.mak`.

### 2. **`tccelf.c`**
   - Modified the interpreter section creation logic to **skip PT_INTERP** if `CONFIG_TCC_ELFINTERP` is an empty string.
   - The check: `if (elfint && *elfint != '\0' && strcmp(elfint, "-") != 0)`
   - This ensures compiled programs do not have a `.interp` section.

### 3. **`config.mak`** (generated by configure)
   - Includes `CFLAGS=-DCONFIG_TCC_ELFINTERP=\"\"` to define the macro as an empty string at compile time.

### 4. **README.md**
   - Updated documentation to note that TinyCC builds disable Linux interpreter embedding for ChrysalisOS compatibility.

## How It Works

1. When TinyCC (`tcc`) compiles a C program, it checks `CONFIG_TCC_ELFINTERP(s1)` to decide what ELF interpreter path to embed in the `.interp` section of the executable.

2. With our changes, this value is an empty string (`""`).

3. The modified `tccelf.c` checks if the interpreter string is empty or "-", and if so, **skips adding the PT_INTERP program header**.

4. The resulting executable:
   - Has **no PT_INTERP section**.
   - Is **statically linked** to libc (via linker flags).
   - Can be **executed directly by ChrysalisOS** without requiring a dynamic loader.

## Usage on ChrysalisOS

Once `tcc` is installed at `/system/bin/tcc` inside ChrysalisOS:

```sh
# Compile a C program using the built-in cc wrapper:
cc hello.c -o hello

# Run the compiled program:
./hello
```

The `cc` command forwards arguments to `/system/bin/tcc`, which uses our modified build to produce ChrysalisOS-native binaries.

## Testing

To verify the build works:

1. **Compile a simple test program on the host**:
   ```bash
   ./bin/tcc -c test.c -o test.o
   ```

2. **Inspect the generated object file**:
   ```bash
   readelf -all test.o
   ```

3. **Inside ChrysalisOS** (if available), try:
   ```bash
   cc test.c -o test_executable
   ./test_executable
   ```

## Troubleshooting

### Issue: "configure: WARNING: unrecognized option --ranlib=ranlib"

This is a known warning from the TinyCC configure script and can be safely ignored. The build will proceed successfully.

### Issue: "error: expected expression before ')' token" in tcc.c:188

This occurred in earlier revisions when `CONFIG_TCC_ELFINTERP` was incorrectly defined. It has been fixed by properly escaping the empty string macro in `config.mak`.

### Issue: "crt*.o not found" when linking with tcc

This is expected if the ChrysalisOS libc and CRT files are not in the search path. It does not affect tcc's core functionality as a compiler for generating object files or producing static executables with bundled runtime support.
